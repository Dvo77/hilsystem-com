## The Big Question

Everything in Foundations is really one question, asked six different ways:

**Would this survive you?**

If someone wrote a label, an address, or a name today — with no conversation to fall back on, no app running, no you standing there to explain it — would a stranger understand it? Would *you*, decades later, having forgotten why you wrote it that way?

This isn't a hypothetical for HIL. It's the literal design premise: *"The physical label is the source of truth." "A photo, a printed label, and a working brain are the minimum viable tools." "Any human, any AI, any scanner can understand your space without a manual."* The HL grammar is one worked example of passing that test. Every Foundations module teaches one piece of how to pass it.

---

## Why this matters (for PATCH's own understanding, not just to recite)

Durable communication shows up everywhere, not just in home inventory — nuclear waste site marker design has wrestled with almost this exact question at civilization-length timescales. That's worth knowing as a real parallel, not just a metaphor: the same underlying problem (how do you make meaning survive when you can't be there to explain it) has serious, considered answers in other domains. PATCH can draw on that connection with a learner who's curious about the "why," without needing to cite specifics.

## The module map

| Module | What it teaches | The durability lesson underneath |
|---|---|---|
| Noun First Lab | Five root nouns, elimination logic | A name has to mean the same thing to anyone, in any era |
| Address Anatomy Lab | The six-segment address format | Structure that's decodable without you there to explain it |
| Counting Rules Lab | Bottom-up, left-right, front-back — the immutable counting rules | Consistency is what makes something learnable once, reusable forever |
| Zone & Sub-Zone Lab | STRUCT/ZONE codes, the `+C` rule | Hierarchy has to be legible from the code itself, not from a map only in your head |
| Display Tiers Lab | Full / Zone-Short / Position-Only, drop-from-the-left-only | Compression that never loses meaning |
| Identity Layers Lab | WHERE / WHAT / NAME, vessel registry | A system built to survive you has to degrade gracefully — partial information still has to be useful |
| **Would This Survive You? — Capstone** | All of the above, applied to a real scenario | The actual test, not a drill about the test |

Six teaching modules, no required order, no gates. The capstone is available from day one — jumping straight in and failing is expected, not a problem to prevent.

## How PATCH should actually use this

- **When tutoring inside any single module,** don't stay purely mechanical ("here's the rule"). Tie it back to the Big Question when it fits naturally — *why* does this rule exist, not just what it is. Not every exchange needs this, but the connection should be available when a learner asks "why does it matter."
- **When proctoring the capstone,** a wrong answer is diagnostic, not just incorrect. Figure out which piece broke (wrong root noun? malformed segment? counted top-down instead of bottom-up? used a new zone where `+C` was right? dropped from the middle instead of the left? confused WHERE/WHAT/NAME?) and point at the specific module that covers it — by name, not a generic "review the material."
- **Socratic questions that reference the Big Question directly** are more valuable here than ones that only test recall of a specific rule. Something like *"If you handed this label to someone in fifty years with no explanation, what would they get wrong?"* tests real understanding in a way "what does STRUCT stand for" doesn't.
- **This document doesn't replace each module's own README** (Guild Proctoring & Tutoring Extension, per `HIL-Guild-Module-Logging-Standard-v3.5.md` Part 9) — it's the layer above them. Load both: this for the "why the category exists," the module's own for "what this specific lesson covers."
