# HIL Sovereign Efficiency Doctrine

## Purpose

HIL is a lean, green-edge, sovereignty-directed system.

Every workload should live where it provides the best balance of:

- Independence
- Cost
- Efficiency
- Maintainability
- Privacy
- Performance

The goal is maximum sovereignty with minimum waste.

---

## Core Principles

### 1. Lean Infrastructure

Use the minimum practical amount of compute, storage, bandwidth, and recurring cost.

---

### 2. Green-Edge Architecture

Keep durable knowledge close to the user whenever practical.

---

### 3. Sovereignty by Direction, Not Purity

HIL prefers portable, replaceable systems.

Cloud services may be used where they provide overwhelming practical value, but the architecture should always preserve a path toward greater independence.

---

### 4. Right Workload, Right Place

Each component belongs where it provides the greatest overall value.

Local systems are preferred for:

- Verified knowledge
- Long-term archives
- Private data
- Backups
- Repeatable retrieval

Cloud systems are appropriate for:

- Authentication
- Public availability
- Stateless AI execution
- Burst compute
- Services that are currently impractical to self-host

---

### 5. Knowledge Compounds

Every verified Wiki.js article reduces:

- AI reasoning
- API calls
- Web searches
- Hallucination risk
- Cost

Knowledge becomes cheaper every time it is improved.

---

### 6. Cloud is Scaffolding, Not Ownership

Google, Cloudflare, Firebase, and similar services provide capabilities—not ownership of HIL knowledge.

Canonical knowledge should remain portable, human-readable, and independently backed up.

---

### 7. Human Authority

AI may retrieve, summarize, organize, and propose.

Humans approve what becomes canonical.

---

## Architectural Intent

The current HIL platform intentionally combines:

- Google
- Cloudflare
- Firestore
- Wiki.js
- GitHub
- R2
- TrueNAS

This is not a compromise of the doctrine.

It is a staged path toward greater sovereignty while remaining practical for a small team.

---

## Long-Term Goal

As the local Wiki.js knowledge base grows, HIL should increasingly rely on verified local knowledge and decreasingly rely on external AI reasoning and public web searches.

Every verified page permanently reduces cloud computation while improving consistency, speed, and trust.

---

## Doctrine Statement

> HIL pursues maximum sovereignty with minimum waste by placing every workload where it provides the best balance of independence, efficiency, cost, maintainability, and trust.
